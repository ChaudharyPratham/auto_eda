Section 3 — Method A

Run Without Docker

Manual setup using a Python virtual environment and Node.js. Requires two terminal windows running simultaneously.

✅
Best for
Local development, debugging, or machines where Docker is not available.

Part 1 — Backend Setup

Open a terminal, navigate to the project root, then run every command below in order.

1
Navigate to the backend folder 
# Windows (PowerShell)
cd "C:\path\to\auto eda\backend"

# macOS / Linux
cd "/path/to/auto eda/backend"
2
Create a Python virtual environment 
python -m venv venv
3
Activate the virtual environment 
# Windows (PowerShell)
.\venv\Scripts\activate

# macOS / Linux
source venv/bin/activate

Your prompt will change to show (venv) when active.

4
Install Python dependencies 
pip install -r requirements.txt

This installs FastAPI, Pandas, PySpark, Pillow, cloud SDKs, and more. Takes ~2–5 minutes on first run.

5
Create the .env file 
# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env

The defaults work out of the box. See Section 5 for all configurable fields.

6
Start the backend server 
python -m uvicorn main:app --reload --port 8000

You should see: Uvicorn running on http://0.0.0.0:8000. Keep this terminal open.

Section 3 — Method A (continued)

Run Without Docker (Frontend)

Section 4 — Method B

Run With Docker Compose

Single command to build and start both backend and frontend. Docker handles all dependencies automatically.

✅
Best for
Sharing with teammates, server deployment, or consistent environments. No Python or Node.js installation needed on the host machine.
1
Navigate to the project root folder 
# Windows (PowerShell)
cd "C:\path\to\auto eda"

# macOS / Linux
cd "/path/to/auto eda"
2
Create the backend .env file 
# Windows
copy backend\.env.example backend\.env

# macOS / Linux
cp backend/.env.example backend/.env

Edit backend/.env to set any optional cloud / database settings (see Section 5).

3
Build and start all containers 
docker compose up --build

First build takes ~5–10 minutes (downloads base images, installs packages). Subsequent starts are instant. You will see logs from both backend and frontend.

4
Open the app in your browser

Go to http://localhost (port 80). The frontend and backend are both running.

:80

http://localhost
:8000
Backend API
http://localhost:8000
/docs

Section 5

Environment Variables Reference

All settings live in backend/.env. Copy backend/.env.example → backend/.env and fill in only what you need. Everything marked OPTIONAL can be left blank — the server starts fine without it.

Backend — backend/.env

# ── Server ────────────────────────────────────────────────────────────────────
HOST=0.0.0.0                       # Leave as-is
PORT=8000                          # Backend port

# ── CORS ──────────────────────────────────────────────────────────────────────
ALLOWED_ORIGINS=http://localhost:5173,http://localhost:3000
# Add your production frontend URL here if deploying

# ── Upload size ───────────────────────────────────────────────────────────────
MAX_UPLOAD_SIZE_MB=500

# ── PostgreSQL (optional) ─────────────────────────────────────────────────────
DATABASE_URL=postgresql://user:password@localhost:5432/autoeda
# Leave blank to skip database. Format: postgresql://user:pass@host:port/dbname

# ── Azure Blob Storage (optional) ────────────────────────────────────────────
AZURE_STORAGE_CONNECTION_STRING=
AZURE_STORAGE_ACCOUNT_NAME=
AZURE_STORAGE_ACCOUNT_KEY=

# ── AWS S3 (optional) ────────────────────────────────────────────────────────
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
AWS_REGION=us-east-1

# ── Google Cloud Storage (optional) ──────────────────────────────────────────
GCP_PROJECT_ID=
GCP_CREDENTIALS_JSON=     # Full path to service-account JSON file

# ── Databricks (optional) ─────────────────────────────────────────────────────
DATABRICKS_HOST=           # e.g. https://adb-1234567890.1.azuredatabricks.net
DATABRICKS_TOKEN=          # Personal access token
DATABRICKS_HTTP_PATH=      # Only needed for SQL Warehouse queries
VariableRequired?Description
HOSTOPTIONALBind address. Keep 0.0.0.0 for Docker; use 127.0.0.1 for local-only.
PORTOPTIONALBackend port. Default 8000.
ALLOWED_ORIGINSOPTIONALComma-separated list of frontend URLs allowed by CORS.
MAX_UPLOAD_SIZE_MBOPTIONALMax file size for uploads. Default 500 MB.
DATABASE_URLOPTIONALPostgreSQL connection string. Leave blank to run without a database.
AZURE_STORAGE_*OPTIONALRequired only if importing data from Azure Blob Storage.
AWS_*OPTIONALRequired only if importing data from AWS S3.
GCP_*OPTIONALRequired only if importing data from Google Cloud Storage.
DATABRICKS_*OPTIONALRequired only if importing data from Databricks DBFS / Volumes.

Section 7

Troubleshooting

Most common errors and how to fix them.

❌ "Could not import module main" when starting uvicorn
You must run uvicorn from inside the backend/ folder: 
cd backend
python -m uvicorn main:app --reload --port 8000
Never run it from the project root or with a path like backend/main:app.
❌ "ModuleNotFoundError" after activating venv
The venv was not activated before installing, or packages were installed globally instead. Fix: 
# Make sure venv is active (see (venv) in prompt), then:
pip install -r requirements.txt
❌ Frontend shows "Network Error" or blank page
The backend is not running, or the port is wrong. Confirm:
  • Backend terminal is still open and shows Uvicorn running
  • http://localhost:8000 returns a JSON response in the browser
  • No firewall is blocking port 8000
❌ "EADDRINUSE: address already in use :::5173" or :::8000
Another process is using that port. Kill it: 
# Windows (find and kill port 8000):
netstat -ano | findstr :8000
taskkill /PID <PID from above> /F

# macOS / Linux:
lsof -ti :8000 | xargs kill -9
❌ Docker: "port is already allocated"
Port 80 or 8000 is used by another container or service. Stop other containers first: 
docker compose down
docker ps -a          # list all containers
docker stop <id>      # stop the conflicting one
❌ "PySpark not available" or Java error in logs
Java is not installed or not on PATH. For files under 100 MB Pandas is used as fallback automatically — no action needed. For files ≥ 100 MB, install Java: 
# Check Java:
java -version
# If missing, download from adoptium.net and add to PATH.
❌ Build error: "Cannot resolve 'buffer/'" from Plotly
The frontend imports plotly.js (source build) instead of the pre-built dist. Check VisualizationPanel.jsx: 
// ✅ Correct:
import Plotly from 'plotly.js/dist/plotly'

// ❌ Wrong:
import Plotly from 'plotly.js'
❌ Upload fails with "413 Request Entity Too Large"
Increase MAX_UPLOAD_SIZE_MB in backend/.env: 
MAX_UPLOAD_SIZE_MB=1000
Then restart the backend server.
❌ Cloud import fails: "azure-storage-blob is not installed"
Cloud SDK packages are listed in requirements.txt but may have been skipped. Reinstall with venv active: 
pip install azure-storage-blob boto3 google-cloud-storage databricks-sdk
❌ Streaming: KafkaTimeoutError — producer can't connect
Kafka inside Docker advertises its internal hostname kafka:9092, which local Python scripts cannot resolve. The docker-compose.yml must define dual listeners: 
KAFKA_LISTENERS: PLAINTEXT://0.0.0.0:9092,PLAINTEXT_INTERNAL://0.0.0.0:29092
KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092,PLAINTEXT_INTERNAL://kafka:29092
KAFKA_INTER_BROKER_LISTENER_NAME: PLAINTEXT_INTERNAL
After editing docker-compose.yml, recreate the Kafka container: 
docker-compose stop kafka zookeeper
docker-compose rm -f kafka zookeeper
docker-compose up zookeeper kafka -d
❌ Streaming: NativeIO$Windows.access0 UnsatisfiedLinkError in PySpark
PySpark on Windows needs winutils.exe to access the local filesystem. Download it once: 
New-Item -ItemType Directory -Force -Path "C:\hadoop\bin"
Invoke-WebRequest -Uri "https://github.com/cdarlint/winutils/raw/master/hadoop-3.3.5/bin/winutils.exe" \
  -OutFile "C:\hadoop\bin\winutils.exe"
Invoke-WebRequest -Uri "https://github.com/cdarlint/winutils/raw/master/hadoop-3.3.5/bin/hadoop.dll" \
  -OutFile "C:\hadoop\bin\hadoop.dll"
Then always start the consumer with $env:HADOOP_HOME="C:\hadoop".
❌ Streaming: init_tables.py — hostname "postgres" not found
The default DATABASE_URL uses postgres (the Docker service name), which only resolves inside Docker. When running locally, override it: 
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5432/autoeda"
.\..\venv\Scripts\python.exe init_tables.py
❌ Streaming: constant HIGH_ERROR_RATE alerts every minute
The mock producer was generating ~20% ERROR logs, which sat right at the 20% threshold — random variance caused most windows to trigger. Fix: lower producer ERROR weight and raise alert threshold. In producer.py change: 
# Before (too close to threshold)
WEIGHTS = [60, 20, 20]   # 20% ERROR
# After (well below threshold)
WEIGHTS = [70, 20, 10]   # 10% ERROR
In spark_consumer.py change the alert threshold from 20.0 to 30.0.
❌ Python 3.14: pandas has no wheel for cp314
pandas 2.2.x does not publish pre-built wheels for Python 3.14. Use Python 3.11 instead: 
# Check which Python versions you have installed
py -0
# Create venv explicitly with 3.11
py -3.11 -m venv venv
.\venv\Scripts\pip.exe install -r requirements.txt --prefer-binary
📖
Need more help?
Check README.md, SETUP.md, and STREAMING_SETUP.md in the project root for detailed feature documentation, API reference, and streaming-specific troubleshooting.
Section 8

⚡ Streaming Analytics Setup

Real-time log pipeline: Kafka → PySpark Structured Streaming → PostgreSQL → React dashboard. Includes a REST ingest API so any application can send events.

🏗️
Architecture
Your App → POST /api/stream/ingest → FastAPI → Kafka "logs" topic → spark_consumer.py (1-min window) → PostgreSQL → Dashboard (polls every 5 s)

1 Prerequisites

RequirementDetails
Docker DesktopMust be running before any docker-compose commands
Python 3.11 venvUse py -3.11 -m venv venv — Python 3.14 breaks pandas wheels
winutils.exe (Windows only)Required by PySpark — see troubleshooting section
kafka-python 2.0.2Included in requirements.txt

2 Start Docker Services

Run from the project root (where docker-compose.yml lives):

# Start Kafka + Zookeeper + PostgreSQL
docker-compose up zookeeper kafka postgres -d

# Wait ~20 s then verify all three are Up
docker ps

3 Initialise Database Tables

cd backend\streaming
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5432/autoeda"
.\..\venv\Scripts\python.exe init_tables.py
# Expected: [init_tables] stream_metrics, stream_alerts, stream_api_keys, stream_events are ready.

4 Start the Mock Producer

$env:KAFKA_BOOTSTRAP="localhost:9092"
.\..\venv\Scripts\python.exe producer.py
# Expected: [producer] Connected to Kafka at localhost:9092

5 Start the Spark Consumer (Windows)

$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5432/autoeda"
$env:KAFKA_BOOTSTRAP="localhost:9092"
$env:HADOOP_HOME="C:\hadoop"
.\..\venv\Scripts\python.exe spark_consumer.py
# Wait ~90 s for first 1-minute window to complete

6 Generate an API Key

curl -X POST http://localhost:8000/api/stream/api-key \
  -H "Content-Type: application/json" \
  -d '{"name": "my-app"}'
# Returns { "data": { "key": "abc123...", ... } } — copy the key, shown once only

7 Send Events

curl -X POST http://localhost:8000/api/stream/ingest \
  -H "X-API-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"service":"payment","level":"ERROR","response_time":1200}'

8 View the Dashboard

Open http://localhost:5173/streaming — data appears after the first 1-minute aggregation window (~90 s after starting the consumer).
